# 进阶：用 Cloudflare KV + 网页后台管理网站数据（可选）

> **先看这里**：默认方案是「静态优先」——只编辑 `data/sites.js`，通过 GitHub 提交自动重新部署。
> 主页是纯静态文件，**访客访问不调用任何函数、不消耗 Cloudflare 免费额度**，这是最推荐的用法。
>
> 本方案是给「不想碰 GitHub、希望直接在网页表单里改内容」的人准备的。
> 它会让主页改为从 KV 读取数据，**每次访问主页都会调用一次函数**，占用免费额度（免费版每天 10 万次函数调用，个人站通常远远够用）。
> 如果你把「不消耗额度」放在第一位，请忽略本目录，继续使用默认静态方案。

## 启用步骤

### 1. 创建 KV 命名空间
在 Cloudflare 仪表盘 → **Workers 和 Pages → KV**，创建一个命名空间，例如 `my-sites-kv`。

### 2. 绑定 KV 到 Pages 项目
进入你的 Pages 项目 → **设置 → 函数 → KV 命名空间绑定** → 添加绑定：
- 变量名称：`SITES_KV`
- KV 命名空间：选择第 1 步创建的

### 3. 设置管理员令牌
在同一页面的 **变量和机密** 中添加机密：
- 名称：`ADMIN_TOKEN`
- 值：设一个只有你知道的随机长字符串（例如 32 位以上）
- 类型选「机密（Secret）」

> 这就是「管理员」：只有拿到这个令牌的人才能通过后台改数据。

### 4. 把文件放到项目根目录
```
# 把 advanced/ 里的函数复制到根目录
cp advanced/functions/api/sites.js  functions/api/sites.js

# 把管理页面复制到根目录（URL 将是 https://你的域名/admin.html）
cp advanced/admin.html  admin.html
```

### 5. 切换到 API 模式
编辑 `data/sites.js`，在最顶部对象里加一行：
```js
"mode": "api",
```
例如：
```js
window.SITE_DATA = {
  "mode": "api",   // ← 加这一行
  "meta": { ... },
  ...
};
```
> 加上后，主页会改为从 `/api/sites` 读取数据；删掉这行即回到纯静态模式。
> 切换模式后需重新部署一次。

### 6. 初始化数据
打开 `https://你的域名/admin.html`，输入令牌 → 点「读取当前数据」。
第一次 KV 是空的，可先把 `data/sites.js` 里 `window.SITE_DATA =` 后面的对象内容复制进文本框（形如 `{ ... }`），再点「保存到 KV」。

之后每次修改：打开后台 → 输入令牌 → 读取 → 改 → 保存。主页刷新即可看到更新，无需重新部署。

## D1 数据库可以吗？
可以，但**没必要**。这个场景只需要存一份 JSON，KV 更简单、更便宜（D1 更适合结构化查询、多表关联）。
如果确实要用 D1，思路是：建一张 `kv` 风格的表（key TEXT PRIMARY KEY, value TEXT），
把 `functions/api/sites.js` 中的 `env.SITES_KV.get/put` 换成 `env.DB.prepare(...).bind(...).run()`，
并在 Pages → 设置 → 函数 → D1 数据库绑定中绑定为 `DB`。接口路径与后台页面都不用改。

## 额度说明（Cloudflare 免费版）
| 资源 | 免费额度 | 默认静态方案 | 进阶 KV 方案 |
| --- | --- | --- | --- |
| Pages 静态请求 | 不限 | ✅ 使用 | ✅ 使用 |
| Workers 函数调用 | 100,000 次/天 | ❌ 不调用 | ✅ 每次访问主页调用 1 次 |
| KV 读取 | 100,000 次/天 | ❌ 不读取 | ✅ 每次访问主页读取 1 次 |

结论：**想要完全不消耗额度 → 用默认静态方案；想要网页后台改内容 → 用 KV 方案**，个人使用基本都在免费额度内。
